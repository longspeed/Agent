Agent Hub

Security

Last updated 23 July 2026

Written from the codebase, not from a certification. Agent Hub is early-stage software. This page states what is actually implemented, including the gaps. It is not a SOC 2 report and does not claim to be one.

Accounts and sessions

  • Passwords are hashed with PBKDF2-SHA256, 260,000 iterations, with a unique random salt per password. Verification is constant-time.
  • Sign in with Google is supported and uses an identity-only scope, separate from the Gmail and Sheets permissions.
  • Sessions are a signed token in an HttpOnly cookie with SameSite=lax, marked Secure in production, expiring after 14 days. The signature is HMAC-SHA256, so the account id inside it cannot be altered.
  • Sign-in is limited to 10 attempts per 5 minutes per IP; sign-up to 5 per hour. Behind a proxy the real client IP is read from a trusted header rather than the socket, so one visitor cannot exhaust everyone's limit.

Your Google connection

  • The OAuth token is encrypted before it is stored (Fernet, AES) and is never written to disk in plain text.
  • The OAuth state parameter is signed and short-lived, so an attacker cannot attach their Google account to your session.
  • Disconnecting from Settings erases the stored token immediately.
  • Mail access is used only to send your outreach and to read the threads Agent Hub started. The rest of your mailbox is not scanned.

Tenant isolation

Every table carries an account id, every query filters on it, and row-level security is enabled on top. Background jobs are visible only to the account that started them. A row index is re-verified against the expected email address before any status is written, so a sheet edited mid-run cannot cause a write against the wrong person.

Guardrails on sending

  • Nothing sends without an explicit confirmation.
  • A row is only eligible when you have approved it by clearing its Status.
  • Sending is capped per account per 24 hours, and to 5 batches per hour.
  • Agent Hub refuses to write into your sheet at all until row 1 carries the full nine-column header. That is your explicit consent that those columns belong to the app rather than to your own notes.
  • No reply is sent to a prospect until you have read and approved it.

Known gaps

Stated openly, because a security page that lists only strengths is not worth reading:

  • Email verification on sign-up is not implemented yet.
  • Password reset is not implemented yet. Contact support if locked out.
  • Self-service account deletion is not implemented yet.
  • Reply drafting sends prospect message text to a third-party language model provider. See the privacy policy.
  • Agent Hub has not completed Google's OAuth verification review, so Gmail access is currently limited to allow-listed test accounts.

Reporting a vulnerability

Email support@agenthub.app with enough detail to reproduce it. We will acknowledge, and we will not pursue anyone who reports in good faith and does not access other people's data.
