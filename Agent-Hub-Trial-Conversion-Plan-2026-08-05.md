## Origin

living inside the product:

1. Show a reply getting handled — seed the trial with a fake thread if needed.
2. Notify when it happens — don't require a tab to stay open.
3. Import a CSV — don't force a Sheet restructure before first value.
4. Follow-ups — two touches minimum.
5. Fix the headline — "Runs itself" attracts the wrong customer and repels you.

This is the same demand-validation signal your own 2026-07-16 design doc
(`office-hours`, still APPROVED) said counts: real friction from a real session,
watched honestly, on the founder's own account. It is not scope creep on top of
that doc — it's the doc's own success criterion arriving.

## Decisions made in review (all confirmed with you)

| # | Decision | Why |
|---|---|---|
| D1 | Single `notifications.py` facade wraps push + email, one call site in `watch_replies.py` | Avoids the scattered-call-site drift TODOS.md already flagged once (operational hygiene bundle) |
| D2 | Single `lead_sources.py` module owns dedup across Sheet / Lead Agent / CSV | Directly prevents the bug shape TODOS.md's "Guard audit" names as having recurred 4 times already |
| D3 | Sequence engine re-checks `reviews_db`/`suppressions_db` immediately before every touch send, not just at schedule time | Closes the exact race `send_reply` was retrofitted for in 2026-07-29 (shipped once without a suppressions check) |
| D4 | Notify-failure visibility reuses `accounts.last_error` (existing column), not new alerting infra | Matches the already-shipped watcher-health pattern; zero new schema |
| D5 | Web Push `endpoint` validated against an allowlist of known push-service hosts before storing/using | Closes an SSRF-lite + reply-content-exfiltration vector — any signed-up account could otherwise redirect notifications to an arbitrary URL |
| D6 | CSV cells starting with `=`/`+`/`-`/`@` are escaped before writing into the Sheet | Standard spreadsheet formula-injection mitigation; this data lands in a real Sheet the account owner opens routinely |
| D7 | CSV import persists per-row (not batch-end) and reports exact landed/failed counts, retry resubmits only the failures | Same shape as the already-fixed `send_outreach.py` batch-end-write bug, applied to reads instead of sends |
| D8 | Sequence engine checks for the operator's own manual follow-up (via `gmail._classify_message`) before firing a scheduled touch, skipping if found | Prevents a contact getting two touch-2's — one from the operator by hand, one from the sequence — on the differentiator this product sells on (careful, non-spammy outreach) |
| D9 | Always-on host provisioning (VPS + the existing systemd unit) is IN SCOPE for this plan | Without it, "notified when it happens" and "follow-ups run themselves" are both still only true while a laptop stays open — the exact complaint that opened this conversation |
